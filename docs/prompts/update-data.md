# update-data — 歌唱データの取り込み(取得 → 下書き → 判断 → 追記)

読む順番(全部読んでから始める): 1. `docs/prompts/_common-context.md` → 2. `docs/prompts/_commands.md` → 3. この文書 → 4. `docs/specs/data-model.md`

> 状態: 運用中。2025年4〜6月の YouTube と、4・5月の X をこの手順で取り込んだ(2026-10-19〜20)。
> - はじめに2本の配信(`yt:rPoEadXC5ck` 初配信・`yt:UnI_NxQlyr8` 弾き語りの歌枠)で試し、手作業のデータと一致した。
> - 決まりは、運用で決まったものを日付つきで足している。

あなたは、しのうたタイムのデータ係です。指定されたコンテンツから歌唱を読み取り、`data/v2/` に追記します。**推測で埋めず、根拠のある行だけを取り込みます。**

## 入力

{{取り込むコンテンツの URL(複数可)}}

URL が無いときは、`python -m src.cli.ingest status` の「未処理」を対象にしてよいか確認すること。

## 制約

- 取得したコメント本文と投稿者名は `data/ingest/cache/`(Git 管理外)にだけ置く。`data/v2/`・コミット・PR の本文に書かない
- `data/v2/` への書き込みは `ingest apply` か `data` の CLI を通す(手で TSV を編集しない。並びと検査がそろわなくなる)
- 推測で曲名・アーティストを補わない。根拠(コメントの行・タイトル・概要欄)に無いものは取り込まず、印を付けて報告する

## 止まって聞く所

1. 職人さんのセットリストのコメントが見つからないとき(下の「取得」の手順を全部やっても無い)
2. `apply` の前。取り込む行・除外する行・印の付いた行の表を出して、承認を待つ(定期実行(自動の取り込み)は未実装で、そのときのブランチと PR の形は未定【要確認】)
3. 既存の曲との結び付けに迷うとき(`match=similar`)

## 決めてよいこと・聞くこと

| 決めてよい | 聞く |
|---|---|
| 雑談・進行の行を除外する、注記を `part`・`note` に分ける | 根拠の無い曲名を入れる(入れない。聞く) |
| 新しい曲の読み(`sort_title`)・アーティストの読み(`sort_name`)を入れる | 既存の曲とまとめる(`merge-song`)、既に登録したコンテンツの取り直し(`--replace`) |
| コンテンツの `kind`(歌枠・初配信など)、タイトルから分かる `default_style` | `kind`・`style` に新しい言葉を足す |

## 手順

1. **取得**: コンテンツごとに、取得結果 JSON を `data/ingest/cache/` に作る。`ingest check <ファイル>` が OK になるまで。
   - YouTube は、月ごとに `ingest list --month YYYY-MM` で本数を確かめ、`ingest fetch --month YYYY-MM` でまとめて取る(API キーは `.env` の `YOUTUBE_API_KEY`。複数のキーは `YOUTUBE_API_KEYS`。種類は自動で判定する)。1本だけなら `ingest from-api <動画ID>`。
     - プレミア公開の歌ってみた・MV(例: 「少女レイ - みきとP / covered by 幽音しの」)は、API ではライブの扱いになり、一覧と `fetch` で `live` になる。`ingest from-api <動画ID> --type video` で取り直す。
   - 同じ月に、本人以外のチャンネルへの出演を洗い出す。
     - `ingest others --month YYYY-MM` の結果から、対象になりそうなものを `ingest from-api <動画ID>` で取る(決まりは「本人のチャンネル以外」)。
     - 本人の X の投稿も確かめる(決まりは「X」)。検索に出ない出演と、X にだけある歌の動画を見つけるため。
     - 週間スケジュールの控え(末尾の「週間スケジュール」)があれば、その月の予定と `ingest status --month YYYY-MM` を照らし合わせる。予定にあるのに取得結果も曲なしの記録も無い配信(他の人のチャンネル・メン限・中止など)を探し、取るか記録するかを決める。
   - ブラウザで取るときは、末尾の「ブラウザでの取得の依頼文」に従う。**評価順の上位だけでは足りない**。2026-10-19 の試行では、正解のセットリストのコメント(高評価 12)が上位 20件に入っていなかった。
2. **下書き**: `ingest comments <content_id>` で候補を見て、`ingest prepare <content_id> [--comment N]`。
   - 候補の順は「セットリスト/セトリの見出し → 曲らしい行(曲名とアーティストに分けられる行)の数 → 時刻の行の数 → いいね」。雑談の目次は時刻の行が多くても下がる。
   - 1位が進行表・目次のようなら、`--comment` でセットリストのコメントを選び直す。
3. **判断**: `data/ingest/staged/<id>.tsv` と `<id>.content.tsv` を直す(下の「判断の決まり」)。完了条件: 取り込む行(`include=y`)は、すべて曲名とアーティストがある。
4. **確認**: `ingest apply <content_id> --dry-run`。【止まる】取り込む行・除外する行・印の付いた行を表にして承認を待つ。
5. **追記**: `ingest apply <content_id>` → `data validate` → `data show`。
6. 終わりの型(下)。

- **月の途中で取り込むとき**(2026年10月で実施): 「10/20 までの分」のように区切って登録し、判断の表にもそう書く。残りは月末に同じ月へ足す。`ingest others` は今までの区間だけを検索する(未来の区間は API が 400 を返すため)。
- **取り込み直し(リラン)**(2025年4〜6月で実施。2026-10-21): 判断の表の無い月や、決まりが変わったあとの月を、今の決まりで照らし合わせ直す。
  1. その月の `data/ingest/cache/` と `data/ingest/staged/` を控える(当時の判断の記録なので消さない)。
  2. `ingest fetch --month YYYY-MM --force` と、本人以外のチャンネルの分は `ingest from-api <id>` でコメントを取り直し、`ingest prepare` で下書きを作り直す。
  3. 新しい下書きと登録済みの歌唱を、時刻と曲で突き合わせる。曲なしの記録の配信は、目次とコメントに歌の行が無いかを見る。
  4. 変える行だけを判断の表に書いて承認をもらう。違いの無い配信は触らない(ショートのタイトルから作った行や、当時ユーザーに確かめて決めた行は、違って当然)。
  5. 登録済みを入れ直すときは `ingest apply <id> --replace`、曲なしを登録に変えるときは `ingest unskip <id>` のあと `ingest apply <id>`。曲や歌唱の一部だけなら `data set`。

## 判断の決まり

- **取り込む行**: 曲名が書かれている歌唱だけ。「自己紹介しながら歌うよ!」のように曲名の無い行は `include=n` にし、`flag` に「曲名が書かれていない」と書く。
- **除外する行**: 雑談・進行・企画の説明(「〇〇紹介」「配信開始」「おつ〇〇」など)は `include=n`、`flag=雑談`。
- **区切り**: 「/」「/」・タブで「曲名/アーティスト/作品/年」に分ける(prepare が行う)。区切りが空白しかない行は、分け方を確かめて直す(画面からの写しではタブが空白になることがある)。
  - 曲名に「/」を含む曲は、prepare が曲名の途中で分けてしまう(2026年10月の「W/X/Y/Tani Yuuki/2021」)。判断で1曲に戻す。
- **曲名の注記**: `(1chorus)` などは `part`、`(リクエスト)` などは `note`(prepare が行う。漏れがあれば直す)。
- **既存の曲との結び付け**: `match=alias/exact` はそのまま。`similar` は、同じ曲なら `song_id` を入れ、違えば空にして新しい曲にする。迷ったら聞く。
- **新しい曲**:
  - `song_kind`: カバー / オリジナル / 即興
  - `sort_title`: 曲名の読み(ひらがな。英語の曲名は空でよい)
  - `work`・`year`: コメントにあれば入れる
- **アーティスト**:
  - 既存の表記に合わせる。
  - 新しいアーティストは `artist_sort` に読み(ひらがな。英字の名前は空でよい)を入れる。
  - 本人は「幽音しの」(読み「かすかねしの」)。
- **feat.**:
  - 「メル feat.IA」は、作り手(`artist`=メル)と歌い手(`feat`=IA)に分ける。prepare が自動で分けるので、分け方だけ確かめる。
  - 読みは作り手のもの(める)。
- **一般検索で確かめる**: 新しい曲は、書き込む前に Web 検索で次のことを確かめる。
  - 作り手、発売・投稿の年、作品(タイアップ)の正しい表記。
  - コメントの表記が違っていたら、正しい表記で登録し、`flag` に「Web 検索で確かめた表記に直した」と書く。2026-10-19 の例: 「俺の青春ラブコメは…」→「やはり俺の青春ラブコメはまちがっている。続」。
  - 元の表記は aliases に残る。
  - 確かめられなかったものは、コメントのとおりにして印を付ける。
- **作品の欄(`work`)**:
  - 元々のタイアップ(アニメの主題歌など)に加えて、**後からの CM 起用なども書く**(2026-10-19 決定)。
  - 取り込みのときに限らず、既に登録した曲でも、気づいたときに `data set songs <song_id> work "<値>"` で足す。
  - 複数あるときは「、」で区切って並べる(例: `アニメ「〇〇」OP、〇〇 CMソング`)。
  - 足すのは、Web 検索で確かめられたものだけ。
  - 公式でないタイアップ(ファンが作った同人のイメージソングなど)は、「非公式」と書いて入れる(例: `ゲーム「ゼンレスゾーンゼロ」エレン・ジョー 非公式イメージソング`。2026-10-21 決定)。
- **即興の歌**:
  - アーティストは「幽音しの」、`song_kind=即興`。
  - 曲名は、コメントに書かれた呼び名を使い、`flag` に「要確認: 曲名はコメントの言葉から」と書く。
  - 「即興」だけのような一般的な名前にはしない。同じ曲として集計されてしまうため。
  - 雑談・ゲーム・運動などの配信の中の歌は、即興の歌だけを登録する(例: 「いただきますの歌」)。**口ずさんだ程度の既存の曲は登録しない**(例: リングフィットの最中の「森のくまさん」)。その配信は「曲なし」で記録し、理由に口ずさんだ曲名を残す(2026-10-20 決定)。
  - ただし、目次に ♪ 付きの行として書かれた歌は、既存の曲でも登録する(2026年10月の朝活の「♪ジングルベル」「♪右肩の蝶」、ダッツ配信の「♪ひとりぼっちの晩餐会」。2026-10-21 決定)。朝活で毎朝歌う「ハッピー・ジャムジャム」も登録する。
  - 目次に無くても、コメントで「〇〇の歌を歌う」とはっきり書かれていれば、即興の歌として登録してよい(2025年4月の「わかるかなの歌」。取り込み直しで登録)。
- **演奏の形**:
  - コンテンツの `default_style` はタイトルから決める(【弾き語り】なら弾き語り)。分からなければ空。
  - 歌唱ごとの `style` は、コメントに「弾き語り」「アカペラ」「音源」とあるときだけ書く。
- **コンテンツの種類(`kind`)**: 歌枠 / 縦型歌枠 / 雑談 / ゲーム / コラボ / イベント / 初配信 / ティザー / 歌ってみた / オリジナルMV / 歌ショート / 切り抜き。
  - 3D のお披露目・3D の歌枠・3D ライブは `kind=イベント`、`default_style=音源`(2026-10-20 決定)。
  - ほかのチャンネルの歌番組(何人かが順に歌う企画)は `kind=イベント`。本人が歌った行だけを取り込み、進行やほかの出演者の歌の行は `include=n` にする。カラオケで歌う番組は `default_style=音源`(2026年5月の JOYSOUND CHANNEL「第1回 バーチャルうたじまん」。2026-10-21 決定)。
- **ギター伴奏**: ほかの人の歌にギターで伴奏しただけのもの(本人は歌っていない)も登録し、`note` に「演奏のみ(ギター伴奏)」と書く(2026年2月の NEWTOWN の音楽イベント。2026-10-20 決定)。
- **ショート・動画**:
  - セットリストのコメントが無ければ、prepare がタイトルから1行を作る(「タイトルから読み取った」の印付き)。
  - タイトルの表記(例: `deco*27`)は、Web 検索で確かめて正しい表記(`DECO*27`)に直す。
  - 演奏の形はタイトルの印から: 【アカペラ】→アカペラ、【弾き語り】→弾き語り、【歌ってみた】→音源。
  - ティザーなど、タイトルが曲名でないもの:
    - 概要欄のクレジット(例: 「かすかなおと」作詞/作曲/編曲)やユーザーの確認で曲が分かれば、その曲の歌唱にする(`kind=ティザー`)。
    - タイトルの文言を aliases に残さないよう、`raw_title`・`raw_artist` は空にする。
  - 複数の曲をつなげたもの(例: ボカロファンテスト)で曲の一覧が分からないものは、下書きのまま保留にして聞く。
  - **公式チャンネルのショート**(2026-10-20 決定): `channel` に公式チャンネル名を入れる。
    - 【LIVE映像】など、説明欄に「元配信はこちら」とあり、登録済みの配信の歌唱を切り出したもの → `kind=切り抜き`(歌唱回数に数えない。元の配信と二重になるため)。`note` に元の配信を書く(例: 「3D歌枠(yt:dMranMUxQIk)の LIVE 映像」)。
    - ほかのメンバーと新しく録ったもの(「以心伝心で歌ってみた」など) → `kind=歌ショート`(数える)。`note` に相手を書く(例: 「茜音カンナとデュエット(以心伝心で歌ってみた)」)。
  - **本人のチャンネルの切り抜きショート**(歌枠の一部を切り出したもの)も `kind=切り抜き` で、`note` に元の配信を書く(例: 「弾き語り歌枠(yt:Z1v3sT_d6uU)の切り抜き」)。説明欄に元の配信が無ければ、同じ曲を歌った直前の配信を探し、決めきれなければ「(推定)」と付ける(2026-10-21)。
- **メンバー限定の配信**(2026-10-20 決定): 歌があれば登録し、`<id>.content.tsv` の `access` を `members` にする(画面には出ない)。タイトルに【メン限】・「メンバー限定」・「メンバーシップ限定」があれば `prepare` が自動で入れる。それ以外はページの「メンバー限定」の表示で確かめて入れる。
- **曲の無いコンテンツ**: 雑談の配信や、歌っていないショートは、ユーザーに確かめてから `ingest skip <content_id> "<理由>"` で記録する(`data/v2/` には入れない)。
- **本人のチャンネル以外**(2026-10-20 決定):
  - **対象にする**: 本人が出演したコンテンツ。コラボ相手のチャンネルでの配信、公式チャンネル(ななしいんく公式など)の動画など。`contents.channel` にチャンネル名を入れる(prepare は `channel` を空にするので、判断で `<id>.content.tsv` に入れる)。
  - **記録しないもの**: ほかの人の MV・ライブ・歌枠を X でリポストしただけで、本人が出ていないもの。誕生日の企画など、出演したかもしれないものは確かめて「出演なし」で記録する(2026-10-20 決定)。
  - **対象外にする**: **ファンが作った動画**(切り抜き、ファンの歌ってみた、字幕編集など)。登録も「曲なし」の記録もしない。
    - 公式かどうかは、チャンネル名だけで決めない。チャンネルの概要欄・事務所の表記・登録者数を確かめる(API の `channels`)。2025年10月に、「Animare Planet【あにまーれプラネット】」(`@animare_planet`)の歌のユニゾン動画を公式と取り違えて登録し、取り消した。このチャンネルはファンのもの(配信の歌をつなげて編集した動画)。
  - **探し方**: 月ごとに `ingest others --month YYYY-MM` で本人以外のチャンネルの動画を洗い出す。
    - YouTube Data API の `search.list` で、検索語「幽音しの」「うるぱんおばけ」(同期3人のコラボ名)を、7日ずつの区間で検索する(1か月で約 1,000 ユニット)。
      1か月まとめて検索すると結果の一部しか返らず、打つたびに件数が変わるため(2026-10-20 に確認)。
    - タイトルにも概要欄にも本人の名前が無い出演(公式の企画、先輩の配信への参加など)は、この検索では見つからない。**X の告知**(下の「X」)で見つける。2025年5月は、面接・コネクトフォー・ジャンボリーの3本を X で見つけた。
      - タイトルに本人の名前が無い他チャンネルの番組(2026年5月の JOYSOUND CHANNEL「第1回 バーチャルうたじまん」。歌っていた)も、`others` では見つからなかった。X の告知の番組名と日時から、下の「X」の API の検索で見つけた。
    - 対象になりそうなものを `ingest from-api <動画ID>` で取り、コメントと概要欄で歌があるかを確かめる。
  - 歌の無いコラボや公式動画は「曲なし」で記録する。
- **X**:
  - 本人の投稿を、Claude.ai のブラウザで月ごとに一覧にしてもらい、結果の JSON を貼ってもらう(ログインが要るため。依頼文は末尾の「X の一覧の依頼文」)。
  - X の検索は、期間が長いと結果の一部しか返らないので、区切って読んでもらう。結果が空白なら表示サイズを広げる。
    - 区切り方は、**日付を指定して1日ずつ**にする(`since:` と `until:` を1日ずらしながら)。
      - 時刻の窓(いちばん古い投稿の時刻を次の `until` にして、古い方へ送る)は取りこぼしが多い。2025年7月は時刻の窓で一巡したあと、日付を指定した取り直しで約60件を補った(6月は時刻の窓で 96件を読めていた)。
      - 2日ずつでも取りこぼす。2025年8月は、2日ずつだと6件だった区間が、1日ずつでは合わせて8件になった。
      - 1日ずつなら、15件を超える日(2025年8月は18〜20件)も読み切れた。
      - 同じ日でも、検索のたびに件数が変わることがある(2025年8月11日は1回目が0件、検索し直すと6件)。0件や件数の少ない日は、検索し直して本当に無いかを確かめてもらう。
      - 全日を2周読んでもらう。2025年10月は、2周目で4日分の投稿が追加で見つかった。
    - ほかの人への返信は外してもらう(2025年7月は 185件のうち 59件が返信だった)。返信かどうかの判定は粗いので、本人の連投の続きが混ざって外れていないかに気をつける。
  - リンクカードで表示されるショートは、URL が `t.co` になり、動画の ID が取れない。カードのタイトルと投稿の時刻で、登録済みのものと照らし合わせる。
  - 引用先の配信の URL は、折り返しで ID が欠けることがある。告知の日時と相手から配信を探す。
    - Web 検索では見つからないことがある。2025年6月は YouTube Data API の検索(検索語は相手の名前、期間は告知の前後)で見つけた。
    - URL の無い告知(引用だけ、番組名だけ)も同じように探す。検索の CLI は無いので、コンテナで `YouTubeApiClient()._get("search", part="snippet", q=<番組名・相手の名前>, type="video", order="date", publishedAfter=<UTC>, publishedBefore=<UTC>)` を呼ぶ(`src/ingest/youtube_api.py`。1回 100 ユニット)。2026年5月は、ナースクイズ大会(瀬島るいのチャンネル)とバーチャルうたじまんをこれで見つけた。
  - 出演者に本人がいないと確かめた配信は、「出演なし(〇〇で確認)。確かめた結果、対象外」と skip で記録する(次の月に同じ配信を調べ直さないため)。
  - YouTube 以外の対象外のプラットフォーム(ニコニコ生放送など)への出演は、`nico:<番組ID>` のように接頭辞を付けて skip で記録する。理由には、出演の確かめ方と歌の有無(分からなければ「未確認」)を書く(2026-10-20 決定)。
    - #ななしおーるいん(ニコ生)の番組 ID は、チャンネルの生放送の一覧 https://ch.nicovideo.jp/ch2649674/live で探せる(本編と VIP 会員限定の延長放送で ID が別。記録するのは本編)。
  - X に付いた動画で歌でないもの(起きた報告など)は、登録も記録もしない。
  - メンバー限定の配信・動画は、API キーでの一覧(`ingest list`)に**出てこない**。メン限の有無は、X の告知(「メン限」「メンバー限定」)で探す。
    - 2025年6月は、X でメン限の BGM の公開を告知していたが、一覧に無かった。
    - 2025年7月は、X の告知の URL から本人のメン限の配信(7/29)を見つけた。これも一覧に無かった。
    - メン限の動画は、API キーではコメントを読めない(403 forbidden)。`ingest from-api` は、コメント0件の取得結果を作る。下書き(`prepare`)の `access` は、タイトルの【メン限】などから自動で `members` になる。
    - コメントを読めないので、歌の有無が分からないときは、ユーザーに確かめてから「歌の有無は未確認(メン限のため API でコメントを読めない)」と skip で記録する(2026-10-20)。歌があると分かれば、`access=members` で登録する。
  - コラボ・出演の告知にある配信の URL は、`ingest status` で登録・記録済みかを確かめ、無ければ `ingest from-api <動画ID>` で取って歌の有無を確かめる。
  - 動画の ID は大文字・小文字を区別する。X の本文から写すと取り違えることがある(2025年5月の例: `ODaEWrswsK8` を `ODaEWrsWSK8` と写した)。「動画が見つかりません」と出たら、まず ID を疑う。
  - 歌の動画は、YouTube のショートと同じものかどうかを確かめてから扱いを決める(二重に数えないため)。
  - YouTube と同じ動画は登録せず、`ingest skip x:<投稿ID> "YouTube の<動画ID>と同じ動画…"` で記録する(確かめ済みだと分かるように。2026-10-20 決定)。

## X の一覧の依頼文(Claude.ai など、X にログインしたブラウザを操作できる Claude に渡す)

2025年6月分で使い、7月・8月分の結果を受けて区切り方を直し、10月分の結果を受けて「2周読む」「前後の端の窓」「途切れた URL のつなぎ方」を足したもの。期間を替えて使う。

```text
X(旧 Twitter)の、ある人の投稿を期間で一覧にし、決まった形の JSON で返してください。保存は不要で、JSON を返すだけで構いません。

対象のアカウント: @Shino_Kasukane_
期間: <YYYY-MM-DD> から <YYYY-MM-DD> まで(日本時間)

     from:Shino_Kasukane_ include:nativeretweets since:<YYYY-MM-DD> until:<YYYY-MM-DD>
   - 「最新」のタブで読む。
   - 時刻で区切る読み方(いちばん古い投稿の時刻を次の until にする)は、取りこぼしが多かったので使わない。
   - 2日以上をまとめて検索すると、取りこぼしが出る。
   - 期間の前後の端(前の月の最終日と、次の月の1日の窓)も読み、日本時間の月初めの早い時間と月末の深夜に抜けが無いかを確かめる(範囲外の投稿は載せない)。
   - 全日を1周読んだら、もう1周読み直す。同じ日でも検索のたびに件数が変わるため。2周目で増えた投稿は足し、日ごとの note に「2周目で◯件追加」と書く。

## 週間スケジュール(毎週。2026-10-22 から)

本人は毎週 X に「【今週のスケジュール！🗓️】」を画像付きで投稿する。これを2つに使う。

- **Information に出す**: 投稿の埋め込みを `data/tweet_embed_code.html`・`data/tweet_height.txt` に保存すると、Information の「今週のスケジュール」に出る(読めないときは X へ案内する)。枠の高さは表示のときにカードに合わせて自動で伸び縮みするので、毎週書き直さなくてよい(`tweet_height.txt` は、合わせられないときの高さ)。
- **取り込みの抜けを探す**: 画像の予定を手元のメモ `docs/plans/ingest-review/週間スケジュール/YYYY-MM-DD週.md`(Git 管理外。YYYY-MM-DD はその週の月曜)に控え、月末の取り込みで照らし合わせる(上の「手順」の1)。

毎週の流れ:

1. 下の依頼文を Claude.ai(X にログインしたブラウザを操作できる Claude)に渡し、JSON を受け取る。
2. `python -m src.cli.twitter_embed_cli <post_url>` で埋め込みを更新する(コマンドは `_commands.md`)。`data/tweet_embed_code.html` に投稿の ID が入っているか、`git diff` で確かめる。
3. JSON の `schedule` をメモに表で書く(日付・時刻・内容・場所・メン限・コラボ相手)。画像の読み違いがありうるので、取り込みの判断の根拠にはしない(抜けを探す手がかりだけ)。
4. コミットはユーザーの指示があったときだけ(`data: 今週のスケジュールを M/D の週にする`)。本番に出るのは、ユーザーが develop → main へ push したとき。

```text

対象のアカウント: @Shino_Kasukane_
対象の週: <YYYY-MM-DD>(月曜)からの1週間。指定が無ければ、いちばん新しい投稿

1. X の検索で、次の検索語を使い「最新」のタブで読む。
